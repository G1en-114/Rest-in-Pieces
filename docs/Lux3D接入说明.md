# Lux3D 在《棺不住》中的作用

核对日期：2026-10-26。本文描述仓库中已经接入的功能；原始设计中的扩展目标见 [设计文档](设计文档.md)。

Lux3D 既用于开发期制作默认角色及主题道具，也通过主菜单「自定义角色」让玩家从照片生成抬棺人或逝者外观。游戏里的移动、抓握、布娃娃、机关、计分和联机由 Godot / GDScript 实现。使用默认或缓存的角色游玩不需要密钥；提交新的照片生成任务时使用玩家自己的 AHOLO API Key 和平台额度。

## 已经接入的资产

| 用途 | 游戏资产 | 代码接入方式 |
| --- | --- | --- |
| 抬棺人 | `game/assets/bearer.glb` | `bearer.gd` 预加载 GLB、实例化模型，读取骨架并驱动双臂 |
| 中国主题道具（3 个） | `game/assets/props/` 下的 `lion`、`paper_kid`、`paper_car` | `props.gd` 加载 GLB，统一高度、居中、落地和哑光材质 |
| 埃及主题道具（4 个） | 同目录的 `sphinx`、`anubis`、`sarcophagus`、`scarab` | `props_egypt.gd` 调用共用 GLB 加载逻辑 |
| 墨西哥主题道具（4 个） | 同目录的 `catrina`、`alebrije`、`sugarskull`、`mariachi` | `props_mexico.gd` 调用共用 GLB 加载逻辑 |

当前抬棺人的 GLB 与本地 `generated/bearer_v2_rig/` 中的自动绑骨结果 SHA-256 一致，模型包含蒙皮骨架。`generated/` 保存原始输出，不进入 Git；游戏使用的 GLB 和贴图放在 `game/assets/`。

自动绑骨提供可变形的骨架；让角色站立、摔倒和抓住棺材的是游戏代码。`bearer.gd` 使用胶囊刚体作为身体、物理球作为双手，再把 `mixamorig:LeftArm` 和 `mixamorig:RightArm`（也兼容下划线前缀）朝向双手位置。游戏还会隐藏绑骨结果中的辅助球，并把材质调整为哑光。

主题道具主要提供外观，碰撞由关卡代码搭建。上述道具的加载函数在资产不存在时会改用代码拼接的简化外观；抬棺人则是必需资产，使用 `preload` 加载。

## 玩家照片角色工作台

1. 在主菜单点 C「自定义角色」，选择玩家一、玩家二或逝者。
2. 选择 PNG/JPEG 全身照片，填写自己的 AHOLO API Key，选择密钥所属的国内 / 国际官方 API。照片最多 16 MiB，客户端检查尺寸并压缩上传。
3. 点「生成并自动绑骨」。`lux3d_client.gd` 通过官方 Asset/OUS 上传照片，调用图生 3D，查询任务，提交人形自动绑骨并下载结果。用户不需要安装 SDK 或运行生成服务器。
4. `character_models.gd` 验证 ≤32 MiB、资源内嵌且具有兼容人形蒙皮骨架的 GLB，并统一角色尺度。成功后保存在 `user://characters/`；失败保留原模型。可手动导入已有 GLB，也可恢复默认外观。
5. `bearer.gd` 保留原有身体与双手，用骨架朝向物理手的位置；`corpse.gd` 保留原有六个刚体与关节，驱动新模型的躯干、头和四肢。默认胶囊外观作为逝者的回退显示。
6. 联机时 `character_sync.gd` 分块同步并校验模型数据，只有房主可决定逝者和房主外观；加入方提交自己的角色。每台电脑的「玩家一」作为自己的联机角色。收到的外观仅作为会话覆盖，离开房间恢复本机保存的模型。

密钥只保留在内存中，不进存档、不进日志、不发给队友。照片会上传平台用于生成，但游戏不把照片写入缓存。任务号、阶段和 API 区域保存在 `user://character_tasks.cfg`，重新输入密钥可继续查询。生成期间可以返回菜单，任务仍在工作台后台继续。

请求发出但未收到任务号时，客户端保留「提交结果待核对」阶段，阻止再次自动创建。用户需先检查平台任务记录，填写实际任务号后继续，或明确放弃本地记录再创建新任务。停止本地等待不取消远端任务，也不能保证远端不计费。

3DGS 背景、4 人联机和任意骨架的自动重定向仍未实现。当前适配器面向 Mixamo / 常见人形命名和 +Y 向上、+Z 朝前的模型，肘膝运动受原有粗粒度物理身体限制。`tools/relay.py` 只负责联机 UDP 中转，不处理 Lux3D 请求。

接口实现按 [AHOLO 官方 Python SDK 文档](https://labs.aholo.ai/api-docs/en/sdk/python) 和仓库已安装的官方 SDK 核对。生成链路由本地 HTTP 模拟服务做回归测试，并于 2026-10-27 用国内官方 API 真实验收（任务号与结果见 [项目报告书](提交/项目报告书.md) 第六节）：T 字站姿的输入可完成生成与绑骨，双臂弯曲的输入会被平台以 `MODEL_NOT_RIGGABLE` 拒绝，游戏会显示该原因。宽檐帽、长裙类模型当逝者时会有网格撕裂。

## 开发期生成流程

1. 在仓库根目录的 `.env` 设置 `AHOLO_API_KEY=你的密钥`，不要提交该文件。`tools/aholo.py` 也支持同名系统环境变量，并优先使用环境变量；可用 `AHOLO_BASE_URL` 覆盖 API 地址。`.env` 的值支持单引号和双引号。
2. 使用 `python tools/aholo.py text3d "提示词" --style cartoon --version G1 --faces 20000` 提交生成任务。角色提示词见 [角色风格](角色风格.md)。
3. 使用 `python tools/aholo.py wait <taskId> --out generated/新资产 --timeout 900` 查询完成状态，保存 `task.json` 并下载输出。请把 `<taskId>` 替换成上一步返回值。默认等待上限是 900 秒，只限制等待生成完成的阶段，不包含下载。超时仅结束本地等待，不取消远端任务；可以用同一 taskId 再次查询。
4. 抬棺人需要绑骨：用 `tools/.venv/Scripts/python.exe tools/rig.py <本地GLB路径>` 上传并创建绑骨任务。此脚本需要 `.env` 和虚拟环境中的官方 SDK；随后仍用 `aholo.py wait` 下载结果。静态摆件通常不需要这一步。
5. 确认模型后将 GLB 和所需贴图放到 `game/assets/` 对应位置。替换抬棺人时需保留预期的骨骼命名、朝向和尺寸；目前不会自动适配任意骨架。道具由加载函数按包围盒统一尺寸。
6. 启动 Godot 检查导入和游戏效果。工具测试不调用真实生成 API，不能替代模型外观、骨架和游戏手感的检查。

查看帮助无需 `.env` 或密钥：`python tools/aholo.py --help`。

## 离线工具回归测试

运行 `python -m unittest discover -s tools/tests -v`。测试通过临时目录和本地 HTTP 服务验证无配置帮助、缺少密钥提示、环境变量优先级、带引号的配置、等待超时、成功下载和失败任务记录，不消耗 Lux3D 额度。
